# Lunch Countdown

Version: 3.1

## Overview

Lunch Countdown is a desktop application built using Python and Tkinter.

The application displays:

- Current Time
- Lunch Time
- Time Remaining Until Lunch

The countdown automatically updates every second and continues counting toward the next lunch period once the current day's lunch period has ended.

Version 3.1 focuses primarily on architectural improvements and ownership separation throughout the application.

---

## Major Changes

### Countdown Ownership Migration

Countdown functionality has been moved from:

```text
main.py
```

into:

```text
countdown.py
```

Responsibilities now include:

- Lunch countdown calculations
- Lunch state determination
- Countdown formatting
- Display updates

---

### UI Ownership Migration

UI creation responsibilities have been moved into:

```text
ui.py
```

The UI module is now responsible for:

- Main window creation
- Label creation
- Button creation
- Settings window creation

This significantly reduces the responsibilities of:

```text
main.py
```

---

### New UI Components Collection

A new structure named:

```python
ui_components
```

is now used to group user-interface objects into a single container.

This improves maintainability and reduces excessive parameter passing throughout the application.

---

## Lunch State System

Version 3.1 introduces a dedicated lunch-state model.

### Pre-Lunch

Displays:

```text
Time Until Lunch

XX hrs : XX mins : XX secs
```

### During Lunch

Displays:

```text
It's Lunch Time
```

The following elements are hidden:

- Time Until Lunch
- Countdown Display
- Counting Down To Lunch

### Post-Lunch

The application automatically begins counting toward the next day's lunch period.

---

## Countdown Formatting

Previous versions displayed:

```text
01:23:45
```

Version 3.1 displays:

```text
01 hrs : 23 mins : 45 secs
```

to improve readability and reduce ambiguity.

## Build Directory Removal

The build directory included in Version 3.0 was intentionally retained as a learning reference for understanding the PyInstaller executable build process and intermediate build artifacts.

Beginning with Version 3.1, the build directory is no longer included because it contains temporary files automatically regenerated by PyInstaller during the build process.

Only the executable located in the dist directory is required for application execution.
